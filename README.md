# Paper · Πελάτες & επισκέψεις

React / TypeScript frontend και ASP.NET Core 10 API με Entity Framework Core. Ελληνικό περιβάλλον, προσαρμοσμένο για υπολογιστή και κινητό.

## Τοπική εκκίνηση σε Windows

Απαιτούνται .NET 10 SDK και Node.js 22.12+ (ή 24 LTS) με npm.

Από PowerShell στον φάκελο του repo:

```powershell
.\scripts\start.ps1 -ExcelPath 'C:\Users\User\Downloads\db2026.xlsx' -Year 2026
```

Άνοιξε **http://127.0.0.1:5080**. Στην πρώτη εκκίνηση ορίζεις εσύ το όνομα, email και password του διαχειριστή. Δεν υπάρχει προκαθορισμένος λογαριασμός. Η φόρμα αρχικής ρύθμισης λειτουργεί μόνο τοπικά σε Development και κλειδώνει μετά τη δημιουργία του πρώτου χρήστη.

Το script εγκαθιστά τις εξαρτήσεις, χτίζει το React και ξεκινά το .NET που εξυπηρετεί και το frontend. Το `start.cmd` ξεκινά χωρίς αρχικό Excel, που μπορεί να εισαχθεί αργότερα από τις Ρυθμίσεις. Μετά το πρώτο build μπορείς να χρησιμοποιήσεις `-SkipBuild` για πιο γρήγορη εκκίνηση. Σταμάτημα με Ctrl+C.

Το `-ExcelPath` εισάγει μόνο αν η βάση δεν έχει πελάτες. Για μελλοντικές ενημερώσεις χρησιμοποίησε την εισαγωγή από το dashboard.

## Λειτουργία

- Προσωπική σύνδεση πωλητή ή διαχειριστή. Όλοι οι πωλητές αναζητούν όλους τους πελάτες.
- Ακριβής αναζήτηση με εννιαψήφιο ΑΦΜ, συμπεριλαμβανομένων των αρχικών μηδενικών.
- Ένα αποτέλεσμα ανά **κωδικό πελάτη**. Υποκαταστήματα με ίδιο ΑΦΜ παραμένουν ξεχωριστά.
- Στην καρτέλα: κωδικός, όνομα, ΑΦΜ, υπεύθυνος πωλητής της πηγής, κατηγορίες με ID, τζίρος ανά κατηγορία και σύνολο.
- Κενές κατηγορίες/τζίρος στο αρχείο σημαίνουν μηδενικές αγορές, σύμφωνα με τις απαιτήσεις. Δεν εμφανίζονται ανύπαρκτα στοιχεία 2025.
- Κάθε αποστολή είναι νέα επίσκεψη στο συγκεκριμένο υποκατάστημα. Η ταυτότητα του χρήστη και η ώρα προέρχονται από τον server. Οι επανειλημμένες προσπάθειες της ίδιας αποστολής δεν δημιουργούν δεύτερη επίσκεψη.
- Το dashboard admin έχει φίλτρα ΑΦΜ, χρήστη και ημερομηνίας, αναλυτικές απαντήσεις και σελιδοποίηση. Οι πωλητές βλέπουν το δικό τους ιστορικό. Ημερομηνίες/φίλτρα σε ώρα Ελλάδας, αποθήκευση σε UTC.
- Ο admin δημιουργεί/απενεργοποιεί λογαριασμούς και προσθέτει/αρχειοθετεί ερωτήσεις. Το ερωτηματολόγιο του καταστήματος περιλαμβάνει 35 ερωτήσεις σε 8 ενότητες, με 116 επιλογές, από το δοσμένο έγγραφο. Όλες οι ενότητες εμφανίζονται. Η βασική δραστηριότητα δέχεται πολλές επιλογές, οι υπόλοιπες ερωτήσεις μία μόνο.
- Κάθε ενότητα μπορεί να μείνει ολόκληρη κενή. Αν απαντηθεί έστω μία ερώτησή της, απαιτούνται όλες οι υπόλοιπες της ίδιας ενότητας. Ο κανόνας ελέγχεται και στο API. Το «Καθαρισμός ενότητας» αδειάζει μόνο τις μη αποθηκευμένες απαντήσεις της φόρμας. Δεν προστέθηκαν επιπλέον επιλογές «Δεν γνωρίζω» πέρα από όσες ήδη υπάρχουν στο έγγραφο.
- Οι τίτλοι ερωτήσεων και οι επιλεγμένες απαντήσεις διατηρούνται ως στιγμιότυπο ανά επίσκεψη, ακόμη κι αν αρχειοθετηθεί μια ερώτηση.

Ο πωλητής στη στήλη ΠΩΛΗΤΗΣ του Excel είναι η υφιστάμενη ανάθεση πελάτη. Δεν δημιουργείται αυτόματα λογαριασμός από το όνομα αυτό. Ο χρήστης που κάνει την επίσκεψη καταγράφεται ανεξάρτητα.

## Εισαγωγή Excel

Αρχείο `.xlsx` έως 8 MB, πρώτο φύλλο, πρώτη γραμμή με τις ακριβείς κεφαλίδες:

```text
ΚΩΔΙΚΟΣ | ΑΦΜ | ΠΩΛΗΤΗΣ | ΠΕΛΑΤΗΣ | ID ΚΑΤΗΓΟΡΙΑΣ | ΚΑΤΗΓΟΡΙΑ | ΤΖΙΡΟΣ
```

Το ίδιο υποκατάστημα μπορεί να έχει μία γραμμή ανά κατηγορία. Διπλή εγγραφή κωδικού/κατηγορίας, αντικρουόμενα στοιχεία του ίδιου κωδικού ή ημιτελή ποσά απορρίπτουν όλη την εισαγωγή, με μήνυμα γραμμής. Δεν συγχωνεύονται αυτόματα κωδικοί ή ΑΦΜ και δεν διορθώνονται επωνυμίες ή σημειώσεις της πηγής.

**Η επανεισαγωγή είναι πλήρες στιγμιότυπο τζίρου για το επιλεγμένο έτος:** αντικαθιστά τις προηγούμενες γραμμές τζίρου αυτού του έτους και ενημερώνει στοιχεία πελατών/κατηγοριών. Οι πελάτες που δεν υπάρχουν στο νέο αρχείο διατηρούνται, με μηδενικό τζίρο στο έτος αυτό, ώστε να μην καταστρέφεται το ιστορικό επισκέψεων. Τα άλλα έτη και οι επισκέψεις διατηρούνται. Απαιτείται πλήρες αρχείο, όχι μόνο οι αλλαγές.

Η εισαγωγή είναι συναλλακτική. Τα πραγματικά Excel, οι βάσεις, τα cookies/κλειδιά και τα τοπικά δεδομένα εξαιρούνται από το Git.

## Βάση δεδομένων

Για άμεση τοπική δοκιμή χρησιμοποιείται **SQLite**, με αρχείο `backend/Paper.Api/App_Data/paper.db`. Τα κλειδιά συνεδριών βρίσκονται στο `App_Data/keys`. Κράτα αντίγραφα της βάσης και των κλειδιών και μην εκθέτεις αυτόν τον φάκελο ως webroot.

Για **SQL Server**, πριν την εκκίνηση:

```powershell
$env:Database__Provider = 'SqlServer'
$env:ConnectionStrings__Database = 'Server=localhost;Database=PaperProductTool;Integrated Security=True;Encrypt=True;TrustServerCertificate=True'
.\scripts\start.ps1 -ExcelPath 'C:\Users\User\Downloads\db2026.xlsx'
```

Η παραπάνω σύνδεση είναι παράδειγμα τοπικού SQL Server με Windows authentication. Σε παραγωγή χρησιμοποιείς πραγματικό hostname, έγκυρο πιστοποιητικό και λογαριασμό βάσης κατάλληλων δικαιωμάτων. Το `TrustServerCertificate=True` είναι μόνο για τοπική ανάπτυξη.

Το API δημιουργεί το αρχικό schema με `EnsureCreated` σε κενή βάση. Η πρώτη έκδοση **δεν παρέχει migrations για μελλοντικές αλλαγές schema**· πριν από αλλαγή υπάρχουσας βάσης χρειάζονται backup και migration. Η αλλαγή provider δεν μεταφέρει δεδομένα αυτόματα. Στην καινούρια βάση επανεισάγεται το Excel· υπάρχοντες χρήστες/επισκέψεις χρειάζονται ξεχωριστή μεταφορά.

Η έκδοση του ερωτηματολογίου εκτελεί συγκεκριμένη προσθετική αναβάθμιση των τριών πεδίων ενότητας/τύπου επιλογής στις υπάρχουσες βάσεις SQLite ή SQL Server. Δεν ξαναδημιουργεί τη βάση. Το περιεχόμενο εγκαθίσταται μία φορά με σταθερά αναγνωριστικά· οι επανεκκινήσεις δεν δημιουργούν διπλότυπα ούτε επαναφέρουν αρχειοθετημένες ερωτήσεις. Οι προηγούμενες επισκέψεις παραμένουν αναγνώσιμες. Το `Survey__InstallDefault=false` απενεργοποιεί την εγκατάσταση του καταλόγου, π.χ. για απομονωμένα tests.

## Ανάπτυξη και έλεγχοι

```powershell
.\scripts\test.ps1
```

Για Vite hot reload: τρέξε το API στο 5080 και, σε δεύτερο terminal, `cd frontend` και `npm run dev`. Άνοιξε το 5173. Ο Vite κάνει proxy τα `/api` στο .NET, με ίδια cookies/CSRF ροή. Για το πρώτο στήσιμο χρησιμοποίησε το 5080.

Στα Windows μπορείς να τρέξεις χωριστά τα δύο μέρη. Πρώτα σταμάτησε οποιοδήποτε ήδη ανοιχτό backend με Ctrl+C, ώστε να είναι ελεύθερη η θύρα 5080.

Terminal 1, από τον φάκελο του repo (αφού έχει γίνει η αρχική εγκατάσταση):

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' run --project backend/Paper.Api --no-restore
```

Terminal 2:

```powershell
cd frontend
npm.cmd run dev
```

Άνοιξε το `http://127.0.0.1:5173`. Κράτα και τα δύο terminals ανοιχτά. Το `npm.cmd` αποφεύγει ασυμβατότητες του PowerShell shim στα Windows. Το `start.cmd` παραμένει η επιλογή για εκκίνηση από ένα παράθυρο, με build του frontend και σερβίρισμά του από το .NET στο 5080. Αν υπάρξει σφάλμα, το παράθυρο μένει ανοιχτό για να διαβάσεις το μήνυμα.

Τα tests ελέγχουν τη διάκριση υποκαταστημάτων, τζίρους/μηδενικά, συναλλακτική επανεισαγωγή, αυθεντικοποίηση, προστασία CSRF, ρόλους, υποχρεωτικές ερωτήσεις, αποφυγή διπλής επίσκεψης και διατήρηση απαντήσεων μετά από αρχειοθέτηση. Τα fixtures είναι συνθετικά και δεν περιέχουν πραγματικά στοιχεία πελατών.

## Φιλοξενία

```powershell
cd frontend
npm ci
npm run build
cd ..
dotnet publish backend/Paper.Api -c Release -o .local/publish
```

Το build του React γράφει στο `backend/Paper.Api/wwwroot`, που συμπεριλαμβάνεται στο publish. Χρειάζονται .NET 10 runtime, SQL Server ή μόνιμος δίσκος για SQLite/κλειδιά, HTTPS, `ASPNETCORE_ENVIRONMENT=Production` και `AllowedHosts` με το κανονικό domain. Μην αντιγράφεις τη βάση ανάπτυξης χωρίς συνειδητή επιλογή.

Ο πρώτος admin σε παραγωγή δημιουργείται με μεταβλητές περιβάλλοντος `Bootstrap__Email` και `Bootstrap__Password` μόνο όταν δεν υπάρχουν χρήστες. Αφαίρεσέ τες μετά την πρώτη εκκίνηση. Μην βάζεις passwords στο repo. Cookies HttpOnly/SameSite, CSRF tokens στις μεταβολές, περιορισμός προσπαθειών σύνδεσης και server-side έλεγχος admin εφαρμόζονται από το API.

Δεν έχει γίνει δημοσίευση σε server. Η σύνδεση με πραγματικό SQL Server πρέπει να επαληθευτεί στο περιβάλλον φιλοξενίας.


## Επισκέψεις, διορθώσεις και χρήση χωρίς σύνδεση

Οι ενότητες είναι tabs: εμφανίζεται μόνο η επιλεγμένη ενότητα. Οι απαντήσεις στις άλλες ενότητες παραμένουν. Αν ξεκινήσει μια ενότητα, χρειάζεται να ολοκληρωθούν όλες οι ερωτήσεις της.

Η καρτέλα ανοίγει το τοπικό πρόχειρο ή την πιο πρόσφατη δική σου επίσκεψη για διόρθωση. Για πραγματικά επόμενη επίσκεψη πάτησε **Νέα επίσκεψη**. Οι διορθώσεις κρατούν το ίδιο ID και αυξάνουν την έκδοση. Ο admin ανοίγει οποιαδήποτε επίσκεψη από τις **Επισκέψεις ομάδας → Επεξεργασία**. Το API κρατά ιστορικό προηγούμενου/νέου περιεχομένου με τον χρήστη και τον χρόνο διόρθωσης (`GET /api/visits/{id}/revisions`). Αν έχει αποθηκευτεί νεότερη έκδοση, εμφανίζεται σύγκριση και απαιτείται ρητή επιλογή πριν από αντικατάσταση.

Στις **Ρυθμίσεις → Ερωτηματολόγιο → Επεξεργασία** ο admin αλλάζει τίτλο, επιλογές, τύπο απάντησης και ενότητα. Οι υπάρχουσες επισκέψεις και τα ήδη αποθηκευμένα πρόχειρα κρατούν το ερωτηματολόγιο με το οποίο ξεκίνησαν. Τα νέα πρόχειρα χρησιμοποιούν την έκδοση που έχει κατεβάσει η συσκευή· για τις πιο πρόσφατες αλλαγές πάτησε **Ανανέωση δεδομένων** πριν βγεις εκτός σύνδεσης.

Η **Εξαγωγή Excel** στις επισκέψεις ομάδας εξάγει τις εγγραφές που ταιριάζουν στα εφαρμοσμένα φίλτρα, πέρα από τη σελιδοποίηση. Το φύλλο Επισκέψεις έχει μία γραμμή ανά καταγραφή και στήλες για τις απαντήσεις, ενώ το φύλλο Ερωτήσεις & οδηγίες εξηγεί τις επικεφαλίδες. Υπάρχει επιλογή τελευταίας επίσκεψης ανά κατάστημα. Περιλαμβάνει ώρες Ελλάδας, ΑΦΜ ως κείμενο και κρυμμένη στήλη έκδοσης. Απαιτεί σύνδεση και admin.

Πριν την πρώτη εργασία χωρίς σήμα:

1. Συνδέσου online στον ίδιο browser/συσκευή και περίμενε **Έτοιμο για χρήση χωρίς σύνδεση**. Κατεβαίνουν το κέλυφος της εφαρμογής, ο κατάλογος πελατών/τζίρων, το ερωτηματολόγιο και έως 100 πρόσφατες δικές σου επισκέψεις για offline επεξεργασία.
2. Κάθε αλλαγή αποθηκεύεται άμεσα σε localStorage. Η **Αποστολή** προσθέτει την καταχώριση σε ανθεκτική ουρά IndexedDB. Το μήνυμα **Αποθηκεύτηκε στη συσκευή. Περιμένει σύνδεση.** σημαίνει ότι δεν έχει ακόμη επιβεβαιωθεί από τον server.
3. Με ανοιχτή την εφαρμογή, η ουρά ελέγχεται κατά την εκκίνηση και κάθε 5 λεπτά. Κάθε έλεγχος επιβεβαιώνει τη σύνδεση με τον server πριν ξεκινήσει η αποστολή. Με το κουμπί «Αποστολή απαντήσεων (Χ/Χ)» ή την αποστολή μίας επίσκεψης γίνεται αποστολή όλης της ουράς, για όλους τους πελάτες του συνδεδεμένου χρήστη. Μετά από κλείσιμο συνεχίζει στην επόμενη εκκίνηση. Το **Στάλθηκε** εμφανίζεται μόνο μετά από επιβεβαίωση. Ληγμένη συνεδρία ζητά σύνδεση στον ίδιο λογαριασμό, διατηρώντας τις καταχωρίσεις.

Κάθε επίσκεψη και κάθε αποστολή έχουν σταθερό αναγνωριστικό. Οι επαναλήψεις μετά από χαμένη απάντηση επιστρέφουν την αποθηκευμένη επιβεβαίωση χωρίς δεύτερη επίσκεψη. Περιεχόμενο, έκδοση, απόδειξη αποστολής και ιστορικό διόρθωσης γράφονται στην ίδια συναλλαγή. Η ουρά συντονίζει τις καρτέλες με προσωρινό lock και η βάση ελέγχει την έκδοση ώστε να αποφεύγει σιωπηλές αντικαταστάσεις.

Η offline χρήση απαιτεί HTTPS στη φιλοξενία (το localhost επιτρέπεται στην ανάπτυξη). Το `127.0.0.1:5173`, το `127.0.0.1:5080` και το domain παραγωγής είναι διαφορετικοί χώροι αποθήκευσης: διάλεξε ένα σταθερό URL ανά συσκευή. Προτιμάται το build που σερβίρει το .NET για δοκιμές offline. Μην καθαρίζεις τα δεδομένα του browser όσο υπάρχουν πρόχειρα/εκκρεμείς αποστολές και μην χρησιμοποιείς ιδιωτική περιήγηση. Η συσκευή κρατά τοπικό αντίγραφο εταιρικών δεδομένων ανά λογαριασμό· χρειάζεται κλείδωμα οθόνης και κατάλληλη διαχείριση εταιρικών συσκευών. Η λειτουργία δεν μπορεί να επαναφέρει μη απεσταλμένα δεδομένα μετά από διαγραφή της αποθήκευσης ή απώλεια συσκευής.

Η αναβάθμιση επισκέψεων είναι προσθετική για SQLite/SQL Server και διατηρεί τις εγγραφές. Πριν εγκατασταθεί σε άλλη υπάρχουσα βάση κράτησε backup. Η τρέχουσα δοκιμή έγινε με SQLite· η σύνδεση SQL Server χρειάζεται επαλήθευση στο δικό της περιβάλλον.


### Αυτόματες διορθώσεις και προβολή ομάδας

Οι ολοκληρωμένες διορθώσεις ήδη σταλμένων επισκέψεων εντάσσονται αυτόματα στην επόμενη αποστολή, ακόμη και αν ο χρήστης δεν πατήσει ξανά το κουμπί. Μία ενότητα που έχει ξεκινήσει αλλά δεν έχει ολοκληρωθεί παραμένει πρόχειρη. Μία εντελώς νέα επίσκεψη απαιτεί την πρώτη ρητή Αποστολή. Δεν υπάρχει χρονικό όριο στις διορθώσεις. Οι συγκρούσεις χρειάζονται πάντα έλεγχο πριν γίνει αντικατάσταση και δεν εμποδίζουν την αποστολή άλλων έγκυρων επισκέψεων. Η μπάρα εμφανίζει τις εγγραφές που χρειάζονται σύνδεση λογαριασμού ή διόρθωση.

Ο admin βλέπει όλες τις επισκέψεις και μπορεί προαιρετικά να φιλτράρει ανά πωλητή. Ο πωλητής βλέπει μόνο τις δικές του: ο περιορισμός εφαρμόζεται στο API ανεξάρτητα από τα φίλτρα που στέλνει. Η προβολή Απαντήσεων εμφανίζει μόνο συμπληρωμένες ερωτήσεις και ενότητες, συν τις σημειώσεις. Τα πλήρη δεδομένα και το ιστορικό διατηρούνται στη βάση.

Το χρονόμετρο 5 λεπτών λειτουργεί όσο εκτελείται η εφαρμογή. Κλειστός browser ή αναστολή της εφαρμογής από το λειτουργικό μπορεί να καθυστερήσει την εκτέλεση. Με το επόμενο άνοιγμα γίνεται νέος έλεγχος. Οι έλεγχοι του frontend εκτελούνται με `cd frontend` και `npm.cmd test` (Node test runner και esbuild).

### Κενές καταγραφές, επιβεβαίωση και διαγραφή

Η αποστολή απαιτεί έγκυρες απαντήσεις ή μη κενές σημειώσεις. Επιτρέπονται επισκέψεις μόνο με σημειώσεις. Μια ξεκινημένη ενότητα χρειάζεται πάντα ολοκλήρωση. Οι μονές επιλογές αποεπιλέγονται με δεύτερο πάτημα και ο μετρητής υπολογίζει μόνο τις επιλογές που υπάρχουν στο ερωτηματολόγιο της επίσκεψης. Ο έλεγχος κενής καταγραφής εφαρμόζεται στη φόρμα, στην ουρά/αυτόματο συγχρονισμό και στα δύο API καταχώρισης.

Με την Αποστολή εμφανίζεται κεντρικό παράθυρο που επιβεβαιώνει είτε «Η επίσκεψη στάλθηκε!» μετά την απάντηση του server είτε «Η επίσκεψη αποθηκεύτηκε στη συσκευή» για εκκρεμή αποστολή. Δεν γίνεται reload και οι τοπικές απαντήσεις παραμένουν αποθηκευμένες.

Στις επισκέψεις ο admin μπορεί να διαγράψει όλες τις καταγραφές, ενώ ο πωλητής μόνο τις δικές του. Το κουμπί ζητά επιβεβαίωση με πελάτη και ημερομηνία. Η ενέργεια απαιτεί σύνδεση: δεν προστίθεται ως εκκρεμής διαγραφή στην offline ουρά. Μετά την επιβεβαιωμένη διαγραφή υπάρχει Αναίρεση.

Το DELETE /api/visits/{id} λαμβάνει expectedVersion στο JSON και εφαρμόζει ανακτήσιμη διαγραφή, έκδοση και audit στην ίδια συναλλαγή. Η εγγραφή αποκρύπτεται από λίστες, ιστορικό πελάτη, offline λήψη και Excel. Το POST /api/visits/{id}/restore κάνει επαναφορά με έλεγχο έκδοσης. Παλιές αποστολές προς διαγραμμένο ID λαμβάνουν HTTP 410 ακόμη και αν επαναλαμβάνουν προηγούμενη επιτυχημένη αποστολή. Η συσκευή κρατά τις τοπικές αλλαγές για έλεγχο και επιτρέπει ρητή μεταφορά τους σε νέα επίσκεψη με νέο ID. Δεν αναδημιουργείται αυτόματα η διαγραμμένη καταγραφή.


### Docker και Render

Το Render τρέχει το .NET μέσω Docker. Το Dockerfile χτίζει πρώτα το React με Node 24 και μετά δημοσιεύει το .NET 10 μαζί με τα στατικά αρχεία. Το τελικό image περιέχει μόνο το runtime και εκτελείται ως μη προνομιούχος χρήστης. Η θύρα ακολουθεί το `PORT` του Render, με προεπιλογή 10000. Η `.dockerignore` αποκλείει τοπικές βάσεις, αρχεία πελατών, κωδικούς και τοπικά build outputs.

Ρυθμίσεις Render:

| Πεδίο | Τιμή |
| --- | --- |
| Service | Web Service |
| Language | Docker |
| Branch | main |
| Root Directory | Κενό |
| Dockerfile Path | ./Dockerfile |
| Docker Build Context Directory | . |
| Docker Command | Κενό |
| Health Check Path | /healthz |

Στα Environment Variables όρισε `Bootstrap__Email` και `Bootstrap__Password` για τον πρώτο admin (12–128 χαρακτήρες, γράμματα και αριθμοί). Αφαίρεσέ τα αφού δημιουργηθεί ο λογαριασμός **σε μόνιμη βάση**. Δεν χρειάζονται build arguments ή secrets μέσα στο Dockerfile. Το image χρησιμοποιεί Production και επιτρέπει τα domains `*.onrender.com`. Για δικό σου domain όρισε `AllowedHosts` με τα επιτρεπόμενα hostnames χωρισμένα με `;`.

**Free Render = προσωρινό demo με την προεπιλεγμένη SQLite.** Το Docker δεν παρέχει μόνιμη αποθήκευση. Σε επανεκκίνηση, sleep ή deploy χάνονται η βάση, οι λογαριασμοί, οι εισαγωγές και οι επισκέψεις του server. Το offline αντίγραφο δεν είναι backup ήδη συγχρονισμένων επισκέψεων. Μην χρησιμοποιείς αυτή τη διαμόρφωση για πραγματικές επισκέψεις.

Για μόνιμα δεδομένα χρησιμοποίησε είτε πληρωμένο service με disk στο `/app/App_Data` (SQLite και κλειδιά σύνδεσης), είτε εξωτερικό SQL Server με `Database__Provider=SqlServer` και `ConnectionStrings__Database` από τα ασφαλή Environment Variables. Η εξωτερική βάση πρέπει να υπάρχει και να είναι προσβάσιμη πριν το deploy. PostgreSQL δεν υποστηρίζεται ακόμη από την εφαρμογή. Σε Free service με εξωτερική βάση, η επανεκκίνηση χάνει τα τοπικά κλειδιά σύνδεσης και μπορεί να ζητηθεί νέο login, χωρίς να χαθούν τα δεδομένα της εξωτερικής βάσης. Για SQLite στον πληρωμένο δίσκο, έλεγξε ότι το UID του container έχει δικαίωμα εγγραφής στο mount και ρύθμισε ανεξάρτητα τακτικά backups βάσης.

Η εισαγωγή του Excel πελατών γίνεται μετά τη σύνδεση ως admin από το interface. Το image και το GitHub δεν περιέχουν τη βάση πελατών.

Τοπικός έλεγχος με εγκατεστημένο Docker:

```sh
docker build -t paper-product-tool .
docker run --rm -p 10000:10000 paper-product-tool
```

Το `/healthz` και η αρχική σελίδα πρέπει να απαντούν στο `http://localhost:10000`. Για login και offline δοκιμές σε Production χρειάζεται HTTPS. Το CI χτίζει το πραγματικό Docker image και ελέγχει την εκκίνηση και τη διάθεση του React.

### Συμπαγής εξαγωγή Excel

Στις Επισκέψεις ομάδας ο admin επιλέγει «Όλες οι επισκέψεις» ή «Τελευταία ανά κατάστημα» και πατά Εξαγωγή Excel. Και οι δύο μορφές χρησιμοποιούν τα εφαρμοσμένα φίλτρα. Η δεύτερη κρατά την τελευταία επίσκεψη μέσα στο φιλτραρισμένο διάστημα ανά κωδικό υποκαταστήματος, διατηρώντας χωριστά υποκαταστήματα με κοινό ΑΦΜ.

Το κύριο φύλλο Επισκέψεις έχει μία γραμμή ανά καταγραφή και ξεχωριστή στήλη ανά απαντημένη ερώτηση. Ερωτήσεις χωρίς καμία απάντηση στο συγκεκριμένο αποτέλεσμα παραλείπονται. Κενό κελί σημαίνει ότι δεν δόθηκε απάντηση, ενώ μια κανονική απάντηση Όχι παραμένει ως Όχι. Οι πολλαπλές επιλογές χωρίζονται με |. Υπάρχουν Excel Table με φίλτρα, εναλλαγή χρωμάτων γραμμών, παγωμένες επικεφαλίδες/πελάτης και πραγματικές ημερομηνίες σε ώρα Ελλάδας. ΑΦΜ και κωδικοί παραμένουν κείμενο.

Το φύλλο Ερωτήσεις & οδηγίες αντιστοιχίζει τους σύντομους κωδικούς στις πλήρεις ερωτήσεις και στις ενότητές τους. Οι πλήρεις τίτλοι υπάρχουν και στα σχόλια επικεφαλίδων. Διαφορετικοί ιστορικοί τίτλοι μιας ερώτησης διατηρούν χωριστές στήλες. ID επίσκεψης, έκδοση, ημερομηνία διόρθωσης και ID ερώτησης υπάρχουν σε κρυμμένες στήλες για ανάλυση/συσχετίσεις χωρίς να επιβαρύνουν την ανάγνωση. Η επεξεργασία Excel δεν επανεισάγει αλλαγές στην εφαρμογή.
